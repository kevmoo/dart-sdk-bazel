# Red-Team Review — Bazel Migration (2026-07-02)

An adversarial review run by three independent reviewers (technical feasibility,
sustainability/process, and backlog-gap audit). All three converged
independently on the same verdict: **Yes-but** — the approach works and the
hardest technical bet has paid off, but the distance from today's state to a
*shippable, multi-variant, test-passing* SDK is larger than the session-by-session
"green" cadence in `STATUS.md` implies, and the shipping **endgame** is almost
entirely absent from the backlog.

This doc captures the findings for the next agent. It is a briefing, not a plan
of record — where it identifies missing work, beads were filed (see the last
section).

---

## Q1 — Is the current approach doable? **Yes, but.**

The genuinely uncertain part is proven: `//sdk:create_sdk` builds green
end-to-end on Linux x64 (session 140: 3,806 actions), the packaged SDK runs, and
the Starlark test matrix shows thousands of passing targets. The
gn-desc→translator + hand-authored C++ overlay + rules_dart + `copy_tree`
assembly thesis **works for the compile/link/assemble path**. No reviewer found
a hard "No."

The walls cluster in the *second half* of the fidelity problem:

| Wall | Evidence | Blocker? |
|---|---|---|
| **Test suite ≈ 0.3% passing** under a full-universe run | `BAZEL_MATRIX_INSIGHTS_AND_RECOMMENDATIONS.md` §1: 2,301 targets → 7 pass / 2,294 fail; ~65% from **inode exhaustion** (>4.6M runfiles symlinks) — cannot run its own tests without RBE | Hard, not impossible |
| **Per-PR CI is analysis-only** | `presubmit.sh:126` = `bazel build --nobuild //sdk:create_sdk` (graph loads, does not compile/test); full build nightly only. This is how PR #15 broke `create_sdk` 5 layers deep without presubmit catching it | No, but "green" is weaker than it reads |
| **Multi-config axes are proofs/stubs** | `build/config/BUILD.bazel:244` product folds *only* the PRODUCT define (not the service-isolate src drop); `sdk/BUILD.bazel:253-308` sanitizer runtimes are `strip --strip-all` copies of the **non-sanitized** binary (semantically fake); arch materializes 62 hand `*_product` targets instead of the promised `select()` folds | No, but "matrix covered" is undemonstrated |
| **No real cross-toolchain** | "green" cross-arch is host-x64 emitting arm64/riscv snapshots via C++ `TARGET_ARCH_*` macros — not a second `cc_toolchain`. Android attempt blocked on NDK (`STATUS.md:27`, `sdk-y6l`) | Hard |
| **Translator inverts on the hard packages** | `runtime/vm/gen_targets.bzl` is literally `pass` — 0 machine / 35 hand-authored; `runtime/bin` is 73 hand / 17 machine. Permanent hand-maintenance tax on the densest C++ surface | No, but the tax is forever |
| **GN is a *permanent* input** | the translator consumes `gn desc`; C++ targets cannot be regenerated without a working GN checkout — directly contradicts DESIGN §4.3's "no permanent dual-system" | The deepest structural issue |

**Bottom line:** doable, and the hardest technical bet already paid off. But
"green" in STATUS means *analysis passes / one config builds* — not *tests pass
on all shipped variants* — and the endgame (deleting GN) is architecturally
unresolved, not merely unstarted.

## Q2 — Is the backlog missing critical work? **Yes — the shipping endgame.**

The build/test surface is well-tracked. The gaps concentrate where it matters
most. Grep across all ~109 beads: **zero hits** for
archive/zip/release/upload/cipd, and **zero** for
determinism/reproducible/byte/golden/hash.

### DESIGN steps → bead coverage (highlights)

| DESIGN §4.1/§4.2 step | Bead coverage |
|---|---|
| Phase 0–2b (toolchain, runtime C++, utils, `create_sdk`) | Covered — green |
| Phase 2c — `samples/` (21 targets) | **MISSING** |
| §4.3 endgame — delete GN / kill translator dependency | **MISSING** → filed `sdk-oss` |
| Distribution — versioned archives + `.sym` + upload | **MISSING** → filed `sdk-itv` |
| Determinism regression guard | **MISSING** → filed `sdk-3x0` |
| rules_dart scope + BCR decision (Open Q #2) | **MISSING** → filed `sdk-3n8` |
| macOS as a supported/CI-gated target | **MISSING** (parked existence-proof only) |

### Beads filed from this review

- **`sdk-oss`** (P1) — Eliminate the GN dependency: make Bazel the sole build system.
- **`sdk-itv`** (P1) — Produce and publish distributable SDK artifacts (versioned archives + symbols + upload).
- **`sdk-3x0`** (P1) — Add a determinism / byte-identical regression guard to CI.
- **`sdk-3n8`** (P1, decision) — Decide rules_dart authoring scope and BCR-publish vs internal ownership.

### Coverage gaps / over-closed beads (not re-filed — flagged for triage)

- **`sdk-tjm`** — closed claiming simulator arch (simarm/simarm64/simriscv64)
  tests pass E2E, but `test_matrix_results.json` shows all six configs
  **Skipped / 0 targets**. Real coverage gap masked by a closed bead — reopen or
  file a follow-up.
- **`sdk-rwz`** (sanitizers) — closed, but per STATUS session 129 it only
  *renames* the plain `dartaotruntime`; genuinely-instrumented asan/msan/tsan
  runtimes are not produced/verified.
- **`issue_00012`** (Unicode 1-to-1 casing) — the one `todo_issues/*.md` with no
  "Tracked in Beads" line and no matching bead (orphan).
- Blocked-count mismatch: `bd stats` reports 4 blocked; `bd list --status
  blocked` returns 1 — DB reconciliation worth doing.
- Open-question decisions live only in DESIGN §6 prose, none as decision beads
  (Reclient-vs-native-RBE, sanitizer-config-ownership, CIPD-URL-validation,
  `pkg/native` code_assets cycle).

### Process risk already tracked

- **`sdk-qoj`** (P1) — replace gemini-code-assist before its **2026-07-17**
  sunset. Gemini's top catch class is generated/embedded code that was never
  executed before push (the clobber/whole-tree-regen incidents, e.g. PR #15's 5
  criticals) — exactly the class the analysis-only presubmit can't catch. Losing
  it without a replacement raises the regression rate on a two-week fuse.

## The honest "definition of done" this review recommends

The project lacks written exit criteria. The four P1 beads above *are* the
missing definition of done — they are the work that blocks declaring "we ship a
Bazel-built Dart SDK," and none had a bead before this review. Pair them with a
decision on the GN-permanence contradiction (`sdk-oss`) and the migration stops
reading as an open-ended science project.
